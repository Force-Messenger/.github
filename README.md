# .github

Служебный репозиторий организации **Force-Messenger**: публичная страница организации и общие для всех репозиториев документы.

| Файл | Где виден |
|------|-----------|
| `profile/README.md` | Страница организации на GitHub — главный публичный текст о продукте |
| `profile/STACK.md` | Состав платформы, ссылка с профиля |
| `profile/SECURITY.md` | Как устроена защита данных — для пользователей, ссылка с профиля |
| `profile/assets/` | Скриншоты для страницы организации |
| `SECURITY.md` | Политика раскрытия уязвимостей. GitHub подставляет её во вкладку Security всем репозиториям организации, где нет своей |
| `SUPPORT.md` | Куда обращаться за помощью. GitHub показывает ссылку при создании issue |

Здесь же GitHub ищет и другие общие файлы организации (`CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `ISSUE_TEMPLATE/`, `FUNDING.yml`) — их можно добавить, когда появятся публичные репозитории с кодом.

## Как обновлять

- Факты о том, что уже работает, держим согласованными с публичным [Планом развития](https://forcemsg.ru/development) (`landing/src/i18n/sections/development.ts`): не отмечаем готовым то, что там ещё в планах.
- Версии технологий в `profile/STACK.md` и бейджи в `profile/README.md` сверяем с `client/package.json`, `client/apps/*/package.json` и `server/build.gradle`.
- **Юридическое здесь не дублируется.** Условия, обработка персональных данных, cookie, правила и порядок жалоб живут только на лендинге (`landing/src/content/legal/*.md` → `forcemsg.ru/legal`); в этом репозитории на них ссылаются. Правка юридического документа не должна требовать правки здесь.
- Скриншоты в `profile/assets/` — копии кадров лендинга (`landing/public/hero/`, `landing/public/screenshots/`). Обновлять оттуда же, чтобы сайт и страница организации показывали одно и то же. В разметке они подключаются по абсолютным `raw.githubusercontent.com`-ссылкам: относительные пути в картинках со страницы организации не работают.
- Ссылки между файлами — абсолютные (`https://github.com/Force-Messenger/.github/blob/master/...`). Относительные пути ненадёжны в обоих направлениях: страница организации рендерится не по пути репозитория, а корневой `SECURITY.md` GitHub показывает в чужих репозиториях организации, где относительная ссылка уведёт не туда.
